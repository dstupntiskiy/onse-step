# One Step · NewClient

Отдельное Angular-приложение для администрирования танцевальной студии. Старый `Client` и серверные проекты не изменены.

## Запуск

Нужны Node.js 20.19+ (или совместимая версия Node 22) и npm.

```powershell
cd C:\Project\one-step\NewClient
npm ci
npm start
```

Клиент: http://localhost:4300. Запросы `/api` проксируются на существующий сервер http://localhost:5000 — адрес настраивается в `proxy.config.json`. Для работы с реальными данными сервер и его база должны быть запущены. Используйте существующие учётные данные студии; демо-аккаунта и подмены API в приложении нет.

```powershell
npm run build
npm test
npm run test:e2e
```

Production-файлы: `dist/browser`. На хостинге нужен fallback маршрутов на `index.html` и проксирование `/api` к серверу. Существующий корневой Dockerfile продолжает собирать старый клиент; переключение production-развёртывания намеренно не выполнено.

## Дизайн и устройство

- Angular 19, standalone-компоненты, lazy-loading страниц. Сохранена основная версия Angular старого клиента для совместимости перенесённых форм.
- Фирменный цвет `#2BB3BA` взят из существующего SVG-логотипа; графитовая навигация, светлый фон, бирюзовые акценты. Токены оформления — `src/styles.scss`.
- Manrope с кириллицей и Material Icons поставляются локально через npm; Google Fonts не требуется.
- На desktop — боковая навигация и недельный календарь, на mobile — нижняя навигация, меню остальных разделов и календарь дня. Календарь занимает всю ширину рабочей области. Недельная сетка прокручивается внутри календаря, не растягивая страницу.
- Календарь написан на Angular Signals и CSS, без FullCalendar. Расчёты дат, пересечений и колонок вынесены в `calendar-layout.ts`.
- Даты показываются в локальном часовом поясе браузера, как в старом клиенте. Границы запросов передаются в ISO; конец периода исключительный. Клиенты за пределами часового пояса студии должны учитывать эту особенность.

## Сохранённые функции

| Область | Возможности |
| --- | --- |
| Вход | Существующий Login API, JWT, выход, возврат на вход при 401; отчёты доступны супер-администратору |
| Расписание | Создание, просмотр, редактирование и удаление занятий, аренды и мастер-классов |
| Повторения | Дни недели и период, изменение одного/всех повторений, удаление экземпляра/серии через прежний API |
| Дежурства | Создание, редактирование, удаление, выбор дежурного и цвета |
| Занятия | Участники группы, отметки посещений, разовые посетители, замена тренера, арендатор |
| Клиенты | Поиск, постраничная подгрузка, создание, редактирование, удаление, телефон и соцсеть, история разовых посещений |
| Абонементы | Создание и редактирование из клиента/группы, 4/8 посещений и безлимит, скидки, произвольная сумма, сроки, комментарий, число посещений, удаление |
| Оплаты | Групповые и разовые оплаты, сумма и комментарий, редактирование и удаление |
| Группы | Создание и редактирование, активность, период, направление, участники и абонементы |
| Тренеры и направления | Создание, редактирование, фильтр активности; цены и ставки направления |
| Отчёты | Абонементы, разовые посещения, дежурства, тренеры, выбор периода, суммы и диаграммы |

Новые удобства: режимы день/неделя, мини-календарь и переход к дате в pop-over по кнопке слева от режимов, поиск по событию/группе/тренеру, фильтры по типу и тренеру, размещение пересекающихся событий рядом, индикатор текущего времени и явные состояния загрузки/ошибки. Выбор даты сохраняет текущий режим и закрывает pop-over; его также можно закрыть клавишей Escape или нажатием вне окна.

События и дежурства видны одновременно: события всегда слева, дежурства справа. Выбранный тип занимает 90% ширины с содержимым, второй — 10% без текста; обе области сохраняют возможность открыть запись. Пересечения рассчитываются отдельно внутри каждого типа. Поиск и фильтры действуют на выбранный тип, второй остаётся видимым для ориентира. Принцип разделения действует в дневном и недельном представлении.

Бизнес-формы и API-сервисы перенесены из `Client`, чтобы сохранить существующие операции и контракты. Новыми являются оболочка, авторизация/навигация, календарь, оформление справочников, общие стили и диаграммы. Проверка прав на сервере остаётся обязательной — клиентский guard её не заменяет.

## Проверки

- `npm test`: тесты дат и раскладки календаря (пересечения, смежные интервалы, полночь, конец месяца, високосный год, переход времени, разделение событий и дежурств 90/10).
- `npm run test:e2e`: браузерные сценарии на Chrome, включая mobile 390 и 320 px. Требуется установленный Google Chrome. Playwright сам запускает dev-server, если он ещё не работает.
- Тестовые ответы API определены только в `tests/e2e/studio.spec.ts` и перехватываются Playwright. В production-сборку они не входят и сервер студии не затрагивают.
- Скриншоты и трассировки записываются в игнорируемую папку `test-results`.

Браузерные проверки с тестовым API не заменяют проверку всех операций на реальной базе. Перед переключением production рекомендуется пройти бизнес-сценарии на тестовой копии БД, особенно повторяющиеся занятия, посещаемость и финансовые отчёты.
