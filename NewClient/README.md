# One Step · NewClient

Основное Angular-приложение для администрирования танцевальной студии. Старый каталог `Client` удален; локальная публикация бекенда и Docker используют `NewClient`.

## Запуск

Нужны Node.js 24.19.0 и npm. Версия Node закреплена в `.nvmrc`;
допустимые версии указаны в `package.json` (`engines`).

```powershell
cd C:\Project\one-step\NewClient
npm ci
npm start
```

Клиент: http://localhost:4300. Запросы `/api` проксируются на существующий сервер http://localhost:5000 — адрес настраивается в `proxy.config.json`. Для работы с реальными данными сервер и его база должны быть запущены. Используйте существующие учётные данные студии; демо-аккаунта и подмены API в приложении нет.

```powershell
npm run build
npm test
npm run test:e2e
```

Production-файлы: `dist/browser`. Корневой Dockerfile собирает `NewClient` через `npm ci` и `npm run build -- --configuration production`, затем копирует результат в `wwwroot` образа бекенда. ASP.NET обслуживает фронтенд, fallback маршрутов на `index.html` и `/api` на порту 5000. При отдельном хостинге фронтенда нужно настроить такой же fallback и проксирование `/api` к серверу.

## Дизайн и устройство

- Angular 22, standalone-компоненты, lazy-loading страниц.
- Сборка и dev-server используют `@angular/build`; старые Webpack-зависимости удалены.
  Официальные миграции сохраняют прежнее поведение обновления компонентов
  (`provideZoneChangeDetection` и `ChangeDetectionStrategy.Eager`) и HTTP-запросов (`withXhr`).
- Фирменный цвет `#2BB3BA` взят из существующего SVG-логотипа; графитовая навигация, светлый фон, бирюзовые акценты. Токены оформления — `src/styles.scss`.
- Manrope с кириллицей и Material Icons поставляются локально через npm; Google Fonts не требуется.
- Общая тема элементов управления — `src/styles/controls.scss`: хорошо различимые поля с контуром, плоские кнопки, сегментированные переключатели, чекбоксы и тумблеры. Приоритет — удобство на сенсорном экране: поля 56 px, кнопки и сегменты от 48 px, увеличенный текст и контрастное выбранное состояние. Оформление использует токены Angular Material и сохраняет стандартное управление с клавиатуры, ошибки и disabled-состояния. На телефонах увеличены зоны нажатия и расстояния между действиями; при ширине до 400 px поля дат располагаются друг под другом, чтобы дата была видна целиком.
- Все формы и подтверждения открываются в боковой панели шириной 720 px справа; при ширине экрана до 760 px панель занимает весь экран. Заголовок и кнопки действий закреплены, содержимое прокручивается отдельно. Сохранены вложенные формы и текущие элементы полей; выбор даты в расписании остаётся pop-over. Общая раскладка панелей — `src/drawer.scss`.
- На desktop — боковая навигация и недельный календарь, на mobile — нижняя навигация, меню остальных разделов и календарь дня. Календарь занимает всю ширину рабочей области. На мобильном расписание помещается в высоту экрана: прокручивается только временная сетка, а шапка, управление датами и нижняя навигация остаются видны. Недельная сетка прокручивается внутри календаря, не растягивая страницу.
- Календарь написан на Angular Signals и CSS, без FullCalendar. Расчёты дат, пересечений и колонок вынесены в `calendar-layout.ts`.
- Даты показываются в локальном часовом поясе браузера, как в старом клиенте. Границы запросов передаются в ISO; конец периода исключительный. Клиенты за пределами часового пояса студии должны учитывать эту особенность.

## Сохранённые функции

| Область | Возможности |
| --- | --- |
| Вход | Существующий Login API, JWT, выход, возврат на вход при 401; отчёты доступны супер-администратору |
| Расписание | Создание, просмотр, редактирование и удаление занятий, аренды и мастер-классов |
| Повторения | Дни недели и период, изменение одного/всех повторений, удаление экземпляра/серии через прежний API |
| Дежурства | Создание, редактирование, удаление, выбор дежурного и цвета |
| Занятия | Участники группы, отметки посещений, разовые посетители, замена тренера, арендатор |
| Клиенты | Поиск, постраничная подгрузка, создание, редактирование, удаление, телефон и соцсеть, история разовых посещений |
| Абонементы | Создание и редактирование из клиента/группы, 4/8 посещений и безлимит, скидки, произвольная сумма, сроки, комментарий, число посещений, удаление |
| Оплаты | Групповые и разовые оплаты, сумма и комментарий, редактирование и удаление |
| Группы | Создание и редактирование, активность, период, направление, участники и абонементы |
| Тренеры и направления | Создание, редактирование, фильтр активности; цены и ставки направления |
| Отчёты | Общая вкладка «Абонементы и разовые», дежурства, тренеры, выбор периода, суммы и диаграммы |

Объединенный отчет использует `GET /api/Report/GetPaymentsReportByPeriod`: суммы абонементов берутся из `Membership.Amount` по `Membership.CreateDate`, разовые — из `OneTimeVisitPayment.Amount` по дате создания оплаты. Общая сумма, направления и дни используют одну выборку и совпадают. Количество разовых — уникальные оплаченные посещения за период (несколько платежей за одно посещение не увеличивают количество). Безлимит и аренда выводятся отдельно. Записи без даты создания в этот отчет не входят.

Границы нового API — UTC-интервал `[startDate, endDate)`, дни группируются в переданном `timeZoneId` браузера. Клиент передает начало выбранного первого дня и начало дня после выбранного последнего: последний день включается целиком, включая переходы времени. Суммы по направлениям сортируются по убыванию общей суммы, количество — по общему количеству, даты — хронологически. Во всех диаграммах бирюзовый обозначает абонементы, сиреневый — разовые. Миграция базы не требуется.

Старые API `GetMembershipsStylesByPeriod`, `GetOnetimeVisitsStylesByPeriod` и `GetPaymentsAmountByPeriod` удалены вместе с обработчиками и DTO. Объединенный отчет использует API `GetPaymentsReportByPeriod`.

Названия разделов находятся в общей шапке. Календарь автоматически показывает день при ширине экрана до 760 px включительно и неделю на более широком экране, в том числе при изменении ширины. Сетка охватывает 8:00–24:00; при открытии прокручивается к 9:00. При обновлении данных и переключении дат сохраняется выбранная пользователем прокрутка. Создание события или дежурства — нажатием на свободное время в сетке.

Новые удобства: мини-календарь и переход к дате в pop-over по кнопке выбора даты, размещение пересекающихся событий рядом, индикатор текущего времени и явные состояния загрузки/ошибки. Выбор даты сохраняет текущий режим и закрывает pop-over; его также можно закрыть клавишей Escape или нажатием вне окна.

События и дежурства видны одновременно: события всегда слева, дежурства справа. Выбранный тип занимает 90% ширины с содержимым, второй — 10% без текста; обе области сохраняют возможность открыть запись. Пересечения рассчитываются отдельно внутри каждого типа. Принцип разделения действует в дневном и недельном представлении.

Бизнес-формы и API-сервисы перенесены из `Client`, чтобы сохранить существующие операции и контракты. Новыми являются оболочка, авторизация/навигация, календарь, оформление справочников, общие стили и диаграммы. Проверка прав на сервере остаётся обязательной — клиентский guard её не заменяет.

## Проверки

- `npm test`: тесты дат и раскладки календаря (пересечения, смежные интервалы, полночь, конец месяца, високосный год, переход времени, разделение событий и дежурств 90/10).
- `npm run test:e2e`: браузерные сценарии на Chrome, включая mobile 390 и 320 px. Требуется установленный Google Chrome. Playwright сам запускает dev-server, если он ещё не работает.
- Тестовые ответы API определены только в `tests/e2e/studio.spec.ts` и перехватываются Playwright. В production-сборку они не входят и сервер студии не затрагивают.
- Скриншоты и трассировки записываются в игнорируемую папку `test-results`.

Браузерные проверки с тестовым API не заменяют проверку всех операций на реальной базе. Перед переключением production рекомендуется пройти бизнес-сценарии на тестовой копии БД, особенно повторяющиеся занятия, посещаемость и финансовые отчёты.
